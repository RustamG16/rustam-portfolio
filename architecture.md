# Architecture: RG × Convenium portfolio (`lab/000-portfolio-russ/site`)

This is the full technical design: stack, data, module boundaries, integration points, and the reason
for each choice. `architecture-essentials.md` is the one-screen outline derived from this file; when
they disagree, this file wins and the outline is regenerated. Visual numbers: `DESIGN.md`. Product
contract: `PRODUCT.md`. Intent: `../.olympus/PLAN.md`. Written in phase 2 (2026-11-06), before the Astro
project exists. Phase 6 scaffolds exactly this tree and must keep the six docs in this folder.

## 1. Stack, and why each piece is fixed

| Piece | Version | Why |
|---|---|---|
| Astro | `^5` (exact version locked in `package-lock.json` at scaffold) | Static HTML per route × language with no runtime. i18n routing is built in. Same family as the lab/003 Meridian precedent (Astro + GSAP + Lenis). |
| GSAP | `3.15.0` exact | Drives the three budgeted effects: ScrollTrigger (hero scrub, reveal triggers) and SplitText (masked lines, free since 3.13, ships in the npm package). Matches Convenium's `motion.ts` vocabulary. |
| Lenis | `~1.3.0` | Smooths wheel input into the scrub (fine pointers only). The old site and Convenium both use it. |
| esbuild | `^0.25.0` (devDependency) | Bundles every client script into **one classic IIFE**. This is the only shape that runs from `file://`: Chromium blocks module scripts on the `null` origin. |
| puppeteer-core | `^25` (devDependency) | QA scripts drive the installed Chrome (`CHROME_PATH`, default `C:/Program Files/Google/Chrome/Application/chrome.exe`). There is no bundled browser download. |
| Node | 22 LTS (CI and local) | Astro 5 requirement satisfied; same as Convenium. |

**No other runtime dependency.** Each new dependency is a Russ decision (Convenium rule).

**Rejected, one line each:**
- **Astro islands / framework components.** There is no interactive state worth a framework, and
  islands emit module scripts that die on `file://`.
- **`@astrojs/sitemap`.** A 20-line endpoint does the same without a dependency.
- **Vite-bundled `<script>` in components.** Module output, so `file://` fails.
- **WebGL.** Fails the activation test (`../.olympus/02-direction.md` § WebGL).

## 5. `file://`: one build that opens from disk

Russ opens builds as files. This is a product requirement (PRD must-do 11), not a convenience. Two
facts drive the design:
- Chromium blocks `<script type="module">` and `fetch()` on the `null` origin.
- Root-relative URLs resolve to the drive root.

1. **Client JS is one classic script.** `scripts/build-client.mjs` runs esbuild with
   `{ entryPoints: ['src/scripts/main.ts'], bundle: true, format: 'iife', minify: true, target: 'es2020', outfile: 'public/js/site.js' }`.
   GSAP, ScrollTrigger, SplitText and Lenis are bundled from npm.
   - `Base.astro` loads it with
     `<script is:inline defer src={withBase('js/site.js') + '?v=' + BUILD_ID}></script>`.
   - Components contain **no** processed `<script>` blocks. The only inline scripts allowed are
     `is:inline` ones: the 404 language swap, and the `js` / `reduced` class set in `<head>`.
2. **Every internal URL goes through `withBase()`** (`src/lib/paths.ts`), which joins
   `import.meta.env.BASE_URL` and the path. There are no hardcoded `/` paths, and `check-tokens.mjs`
   greps for `href="/` and `src="/` in `src/`.
3. **`<html data-base>`** carries the base for scripts. Frame and film URLs are built as
   `document.documentElement.dataset.base + 'frames/hero/desktop/frame_0001.jpg'`.
4. **`npm run build:file`** runs `FILE_BUILD=1 astro build` and then
   `node scripts/relativize.mjs dist-file`. The relativizer:
   - In every `.html`, rewrites root-relative values of `href`, `src`, `srcset`, `poster`,
     `data-base`, `data-src`, `data-poster` and `data-film`, plus `url(/…)` in inline styles, into
     paths relative to that file. If the target is a directory or ends in `/`, it appends
     `index.html`. It keeps `?query` and `#hash`.
   - In every `.css`, rewrites `url(/…)` relative to the CSS file (for example, `_astro/x.css` → `../fonts/…`).
   - Leaves absolute `https:` URLs (canonical, OG, hreflang, external links) alone.
   - Fails (exit 1) if any root-relative URL survives.
5. **Media loads through element events, never `fetch`.** That means `<img>` `onload` plus
   `decode()`, and `<video>` `loadeddata` / `canplay`. Nothing is gated on HEAD requests. `qa/file-url.mjs`
   opens `dist-file/index.html` and `dist-file/cv/index.html` from disk and asserts every frame loaded.

## 8. Client scripts

`src/scripts/main.ts` is the bundle entry. It is written once by phase 6 and frozen. Its init order:

1. **`env.ts`.** Reads `MQ` (built from `BP = { sm: 640, md: 960, lg: 1200 }`), `reduced`, `finePointer`,
   `base` and `lang`. It registers the GSAP plugins once: ScrollTrigger and SplitText.
2. **`lenis.ts`.** Only when `finePointer && !reduced`:
   - `new Lenis({ autoRaf: false, smoothWheel: true, syncTouch: false, lerp: 0.1 })`
   - `lenis.on('scroll', ScrollTrigger.update)`
   - `gsap.ticker.add((t) => lenis.raf(t * 1000))` and `gsap.ticker.lagSmoothing(0)`
   - `window.__lenis = lenis`, for QA parking (memory `lenis-breaks-playwright-stability`)

   Touch keeps native scroll.
3. **`header.ts`, then `cursor.ts`.**
4. **Page modules,** each guarded by a `data-*` hook on the page and each exporting `init(env)`:
   - `hero/hero.ts` (`[data-hero]`)
   - `works/float-preview.ts` (`[data-works]`)
   - `reveal.ts` (`[data-reveal]`)
   - `cv/spine.ts` and `cv/lightbox.ts`
5. **`document.fonts.ready.then(() => ScrollTrigger.refresh())`.**

ScrollTriggers carry `refreshPriority` in page order: hero −3, header triggers −2, works 0, reveal 1,
tab bar 2.

**Ticker hygiene.** Every `gsap.ticker` callback body is wrapped in try/catch. One exception there kills
Lenis, ScrollTrigger and every tween on the page (memory `lab-000-portfolio-hero-scrub`).

### 8.1 `FlipbookScrubber.ts`: port rules (phase 7)

This is a TypeScript port of `site/main.js` `FlipbookScrubber` (the 2026-08-10 hold-everything rebuild).
The rules are load-bearing:

1. **Hold everything.** All 180 (desktop) or 90 (phone) frames become `<img>` elements at construction
   and are held for the whole session. No windowing, eviction, blob cache, tiers, worker or queue.
   **Never window a scrub.**
2. **Coarse first.** Request order: frame 1, then every 8th frame (indices 0, 8, … 176 / 0, 8, … 88),
   then the last frame, then the rest in index order. The coarse set gets
   `fetchPriority = 'high'` and the rest `'low'`.
3. **Decode before counting.** An index joins `loaded` only after `img.decode()` resolves (or rejects,
   then falls back to `onload`).
4. **`nearestLoaded(i)`** returns the exact frame, else searches outward up to `SEARCH_RADIUS = 8` (the
   coarse step, so any playhead has a neighbour once the coarse set is in), else the last painted
   frame.
5. **The frames are JPEG only:** baseline (never progressive) and **never AVIF**. AVIF decodes 5–10×
   slower, and the scrubber pays decode on the critical path. Desktop is 1920×1080, phone 720×1280.
6. **Element events, never `fetch`.** This is what makes `file://` work.
7. **Cover-fit draw** on a 2D context with `{ alpha: false }`. The backing store is sized from the
   canvas's own box through a ResizeObserver, never `innerWidth`. The DPR is clamped so the cover
   scale never exceeds 1. Letterbox in noir beyond 2.4:1.
8. **Removed from the old engine:** the seam glitch, the bloom (a radial gradient, which is now
   banned), the grade flash and scanlines. **Never read pixels back** from the canvas being drawn to.
9. **The frame set is picked once at load:** `matchMedia('(orientation: portrait)')` gives phone, else
   desktop. A resize re-fits the cover and never swaps sets.
10. **The playhead comes from the scrubbed value, never `ScrollTrigger.progress`.**
    - **The tween:** one GSAP tween animates a proxy `{ p: 0 → 1 }` with
      `scrollTrigger: { trigger: section, start: 'top top', end: () => '+=' + runwayPx, scrub: 1 }`.
    - **The draw:** a ticker callback draws `round(clamp01((p − 0.14) / 0.72) × (count − 1))`.
    - **Why:** `progress` hits 1 before the smoothing catches up, so gating on it freezes the last
      pass.
11. **The beat outputs are CSS custom properties** on the stage, written from `p` each tick: `--film`,
    `--title`, `--chrome`, `--wordmark`, `--enter`, `--rule`. No React-style re-render, no layout
    reads.
12. **The matte shows only when `p ≥ 0.86` *and* `painted === count − 1`.** It can therefore never sit
    over a different frame.
13. **QA hooks:** `window.__scrubber` exposes `count`, `loaded`, `displayIdx` and `painted`. Once
    `loaded.size === count`, `Math.round(displayIdx) === painted` must hold at every scroll speed.
14. **Reduced motion and no JS** get no scrubber. The stage shows `frame_0180.jpg` (phone
    `frame_0090.jpg`) as an `<img>`, with the matte and the wordmark static.

### 8.2 Reveal and float preview (phase 8)

- **`reveal.ts`** handles two cases:
  - **Lines:** `SplitText.create(el, { type: 'lines', mask: 'lines', autoSplit: true, aria: 'auto', onSplit: (s) => gsap.from(s.lines, { yPercent: 110, duration: 0.62, ease: 'expo.out', stagger: 0.07, scrollTrigger: { trigger: el, start: 'top 85%', once: true } }) })`.
  - **Media blocks:** `gsap.from(el, { y: 24 (14 below 960), opacity: 0, duration: 0.78, ease: 'expo.out', scrollTrigger: { trigger: el, start: 'top 85%', once: true } })`.

  `autoAlpha`, `visibility` and `display` are never used. Under reduced motion it does nothing.
- **`float-preview.ts`** runs only for fine pointers ≥ 960 px.
  - **The frame:** a 320×400 frame follows the pointer with a lerp of 0.14 in one rAF loop, and stops
    when the pointer leaves the list.
  - **Entering a row:**
    - set the poster at once;
    - assign `film.mp4` to the `<video>` `src` on first hover (`preload="none"` until then), then
      `play()` it once `canplay` fires;
    - open with a clip-path over 0.78 s.
  - **Leaving:** close in 0.24 s and pause.
  - **Stale frames:** a generation token per hover means a late `canplay` from a previous row can
    never show the wrong film. Never sample `readyState` straight after setting `currentTime` (memory
    `lab-000-portfolio-work-previews`).
  - **Keyboard focus** shows the poster only.

## 14. Deploy

`.github/workflows/deploy.yml` keeps today's shape: check, then deploy, atomic and queued.

```yaml
on: { push: { branches: [main] }, workflow_dispatch: {} }
permissions: { contents: read, pages: write, id-token: write }
concurrency: { group: pages, cancel-in-progress: false }
jobs:
  build:            # the check job: nothing deploys unless every gate passes
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: '22', cache: 'npm' }
      - run: npm ci
      - run: npm run check          # check-copy, check-tokens, build (incl. build-client), check-refs dist, check-frames, check-facts-dist
      - uses: actions/upload-pages-artifact@v3
        with: { path: dist }
  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment: { name: github-pages, url: ${{ steps.deployment.outputs.page_url }} }
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4
```

## 15. Performance design

- **LCP** is the hero H1 wordmark: real text, preloaded Archivo, no image dependency.
- **The frames don't block anything.** They start after `DOMContentLoaded`, so they never hold up LCP.
- **The loader** waits at most 0.9 s, for the coarse set only.
- **Film and portrait loading:**
  - Works films are `preload="none"`, fetched on first hover.
  - Posters below the fold use `loading="lazy"`.
  - Pillar portraits are `loading="lazy" decoding="async"` with explicit `width`/`height`.
- **INP:**
  - Hover and scroll handlers only write transforms and custom properties.
  - No layout reads inside the ticker.
  - The cursor and float loop share one rAF.
- **Budgets** are in DESIGN.md `budgets`. Phase 10 measures them, and phase 11 confirms with
  Lighthouse.
